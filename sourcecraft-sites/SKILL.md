# SourceCraft Sites: опубликовать статический сайт

Скилл размещает простой статический сайт на бесплатном хостинге SourceCraft Sites из нового публичного репозитория. Работает только через локальный CLI `src` и `git`. Репозиторий клонируется в директорию `sites/<repo>` в текущей директории (путь можно изменить параметром `clone_dir`); вне этой директории скилл ничего не создаёт.

## Предусловия

- CLI `src` установлена. Проверка: `src auth status` — в ответе должно быть `Successfully authenticated`.
- Организация и репозиторий должны быть публичными: SourceCraft Sites публикует сайты только из публичных репозиториев в публичных организациях.

Если `src` не установлена или не авторизована, остановись и скажи пользователю, что нужно выполнить `src auth setup` (или `src auth login`), и дождись подтверждения, что авторизация прошла.

## Параметры

Параметры передаются в промпте или уточняются в чате у пользователя. Не начинай работу, пока не известны организация и имя репозитория.

- `org` (обязательный) — слаг организации, например `myorg`.
- `repo` (по умолчанию `my-site`) — слаг репозитория. Допустимы только ASCII-символы: латинские буквы, цифры, дефисы, подчёркивания. Если репозиторий с таким именем уже существует, предложи пользователю другое.
- `greeting` (по умолчанию `Привет!`) — текст приветствия на главной странице. Страница всегда содержит подзаголовок с именем репозитория в формате `org/repo`.
- `description` (по умолчанию пусто) — описание репозитория.
- `clone_dir` (по умолчанию `<текущая директория>/sites/<repo>`) — путь, куда клонировать репозиторий. Если параметр не задан, создай в текущей директории папку `sites` и клонируй репозиторий в `sites/<repo>`.

## Шаги

1. Проверь предпосылки: `src auth status`. При ошибке — прервись и попроси пользователя авторизоваться.

2. Создай публичный репозиторий:

   ```
   src repo create <org> --slug <repo> --visibility public --default-branch main --description "<description>"
   ```

   Если репозиторий с таким именем уже существует, команда вернёт ошибку — предложи пользователю другое имя и повтори.

3. Склонируй репозиторий. По умолчанию используй директорию `sites` в текущей директории: создай её, если её нет, и клонируй так, чтобы клон оказался в `sites/<repo>`, а не рядом с файлами текущего проекта:

   ```
   # PowerShell
   New-Item -ItemType Directory -Force -Path "sites"
   src clone <org>/<repo> sites/<repo>

   # Bash
   mkdir -p sites
   src clone <org>/<repo> sites/<repo>
   ```

   Если пользователь явно указал `clone_dir`, используй его как путь назначения вместо `sites/<repo>` (создай родительские директории при необходимости).

   Только что созданный репозиторий может быть пустым — предупреждение при клонировании пустого репозитория допустимо.

4. В клоне создай файлы:

   `site/index.html` (кодировка UTF-8, `<html lang="ru">`, минимальная страница с заголовком из `greeting` и подзаголовком `org/repo`). Пример структуры:

   ```html
   <!DOCTYPE html>
   <html lang="ru">
   <head>
     <meta charset="utf-8">
     <meta name="viewport" content="width=device-width, initial-scale=1">
     <title>Привет!</title>
     <style>
       body { font-family: system-ui, sans-serif; margin: 0; min-height: 100vh; display: grid; place-items: center; background: #f5f3ef; color: #1f1f1f; }
       main { text-align: center; padding: 2rem; }
       h1 { font-size: 2.5rem; margin: 0 0 .5rem; }
       p { font-size: 1.1rem; color: #555; }
     </style>
   </head>
   <body>
     <main>
       <h1>Привет!</h1>
       <p>Это статический сайт из репозитория org/repo</p>
     </main>
   </body>
   </html>
   ```

   `.sourcecraft/sites.yaml`:

   ```yaml
   site:
     root: site
     ref: main
   ```

5. Если агент работает в директории, где уже находятся файлы сайта - используй эти файлы для наполнения сайта внутри `sites/<repo>`, вместо приветственного файла `index.html`.

6. Запушь изменения в основную ветку `main`:

   ```
   git add -A
   git commit -m "Add static site"
   git push -u origin main
   ```

   Пуш использует credential helper `src`. Если git запрашивает авторизацию, попроси пользователя выполнить `src auth setup-git` и повтори пуш.

7. Сообщи результат:

   - Адрес сайта: `https://<org-slug>.sourcecraft.site/<repo-slug>`. Используй фактические слаги организации и репозитория из параметров.
   - Сайт станет доступен в течение нескольких минут после пуша; в дальнейшем он обновляется автоматически при пуше в `main`.
   - Браузер не открывай — только выведи адрес.
   - Укажи путь, куда склонирован репозиторий, чтобы пользователь мог внести правки или удалить клон.

## Troubleshooting

- `src: command not found` — CLI не установлена; прервись и сообщи пользователю, как установить `src`.
- Ошибка авторизации — попроси пользователя выполнить `src auth setup`, затем повтори шаг.
- `git push` требует логин/пароль — попроси выполнить `src auth setup-git` и повтори пуш.
- Репозиторий уже существует — предложи другое имя и начни шаг 2 заново.
- Сайт отдаёт 404 — предложи подождать несколько минут; проверь, что репозиторий и организация публичные, файл `.sourcecraft/sites.yaml` лежит в ветке `main` и директория `site` с `index.html` существует.
- Организация приватная — Sites не публикует сайты из приватных организаций; сообщи об этом пользователю.
