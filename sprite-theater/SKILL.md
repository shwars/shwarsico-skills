# Sprite Theater

Создавать самостоятельный спектакль с цветными вырезанными фигурками,
реквизитом, декорациями и репликами. Изображения и движения служат конкретной
постановке; число сцен, длительность, стиль и язык не фиксированы.

## Начать с материала и выбора проигрывателя

1. Прочитать применимые `AGENTS.md`, исходный текст и относящиеся к фрагменту
   карточки wiki. Не использовать пересказ вместо доступного первичного текста.
   Для источников и адаптации прочитать [sources.md](references/sources.md).
2. Если пользователь не задал технологию, **спросить в диалоге**: pygame,
   статическое веб-приложение или оба варианта. Не выбирать молча. Уже заданную
   технологию не переспрашивать. Pygame подходит для отдельного настольного
   приложения; web — для браузера, телефона и распространения без установки.
3. Уточнять фрагмент, аудиторию, длительность и стиль только при существенной
   неопределённости. Сохранять данные пользователем предпочтения. Советские
   экранизации, четыре сцены и конкретные реплики прежней постановки — не общий
   стандарт. По умолчанию звук не добавлять.
4. Определить сцены, участников, конфликт и изменение состояния, реплики,
   движения и реквизит. Отличать канон от сокращения и художественного допущения.
   Канонические карточки и факты wiki не переписывать.

## Сначала character sheet, затем спрайты

Прочитать [characters.md](references/characters.md) **до генерации изображений**.
Для каждого изображаемого персонажа сначала найти совместимый character sheet
или создать и осмотреть новый. Все листы состава подготовить до игровых поз.
Затем каждую позу генерировать с листом именно этого персонажа как референсом.
Сидячая поза, спина и другой костюм не должны случайно менять лицо и пропорции.

В wiki искать листы по устойчивому ID и визуальному профилю, а не только имени
файла. Предложить хранить их один раз в общей директории wiki, соответствующей
её структуре (например, `wiki/characters/sheets`). Писать туда после выбора
пользователем общего хранения; до этого использовать каталог спектакля.
Переиспользовать совместимые листы, сохранять существующие версии. Невидимый
рассказчик листа не требует; повторяющейся массовке допустим общий типовой лист.

Генерировать напрямую встроенным генератором Codex **GPT Images**, без
обязательного imagegen-скилла. Сохранять промпты, результаты и использованные
референсы. Следовать явному выбору другого инструмента пользователем. Если
генератор недоступен, сообщить об этом и подготовить остальную постановку,
не выдавая технические заглушки за готовых персонажей.

## Собрать спектакль на переносимом шаблоне

Прочитать [format.md](references/format.md) и справочник выбранного движка:
[pygame.md](references/pygame.md), [web.md](references/web.md), при `both` — оба.
Использовать встроенные шаблоны, а не переписывать часы и восстановление сцены.

```text
python /skill/scripts/theater_project.py init --backend web --output /project
python /skill/scripts/theater_project.py prepare --project /project
python /skill/scripts/theater_project.py validate --project /project
```

`/skill` — абсолютный путь скилла, `/project` — каталог результата. Для `init`
выбрать `pygame`, `web` или `both`. Каталог с существующими файлами по умолчанию
не перезаписывается; `--overwrite` использовать только при явном разрешении
заменить шаблонные файлы. `init` создаёт пустой каркас, не художественный результат.
Для подготовки/проверки нужен Pillow из `scripts/requirements.txt`.

Сценарий `script.json` и `assets/manifest.json` — редактируемые исходники.
После их изменения запускать `prepare`: он проверяет данные, вычисляет границы
спрайтов, встраивает данные и шрифт для `file://`. При `both` оба проигрывателя
используют один сценарий и локальные ассеты. Каталог результата самодостаточен;
wiki и скилл не нужны для воспроизведения.

Сохранить инструкцию запуска **в проекте спектакля**, исходные промпты и
референсы, источники, сведения об адаптации и лицензии. Проверить читабельность,
целые контуры, настоящий alpha-канал и сходство поз с character sheet.
Не обрезать шляпы, обувь и реквизит; дефекты изображения исправлять генератором.

## Проверить результат

Использовать [verification.md](references/verification.md). Проверить полный
показ и управление, перемотку вперёд/назад и смену поз, паузу всех элементов,
восстановление реквизита и смену сцен. Сделать проверочные кадры всех сцен.
Структурный валидатор не проверяет литературную точность, сходство лиц или
читаемость бабблов: отдельно осмотреть изображения и сверить сценарий с текстом.
Сообщить, что проверено, где находится запуск и какие ограничения остались.
