# Проверка спектакля и скилла

## Каждая постановка

1. `prepare`, затем `validate`. Проверить ID, источники, положительные длительности,
   порядок кадров, ссылки на ассеты и родителей реквизита. PNG фигур и реквизита
   должны иметь прозрачные и видимые пиксели. Проверить привязку поз к sheet.
2. Сверить причину каждого действия, порядок, время и место с исходником.
   Проверить, что придуманные реплики отмечены, канон не переписан. Общую wiki
   сверить по diff: разрешены согласованные sheet, не случайные изменения фактов.
3. Осмотреть листы и позы вместе: лицо, костюм, пропорции, целые края, правильный
   ракурс. Проверить реквизит до/после поднятия и при перемотке назад.
4. Пройти полный показ; проверить паузу во время входа, жеста, печати и занавеса;
   раскрытие/пропуск реплики, выбор каждой сцены, повтор после конца, перемотку.
   Сделать кадры всех сцен при большом и малом окне. Не допускать наложения
   баббла на лицо или выхода текста за границы; длинную реплику разделить.
5. Web: `file://`, HTTP и подкаталог; desktop, phone и промежуточная ширина,
   fullscreen/fallback, скорость, клавиатура и touch; скрытие вкладки и возврат.
   Проверить отсутствие внешних запросов и ошибки отсутствующего ресурса.
   Указывать реальные проверенные браузеры; эмуляция не равна проверке устройства.

## При изменении самого скилла

```text
python /skill/scripts/test_theater.py
python /skill-creator/scripts/quick_validate.py /skill
```

Нейтральная тестовая постановка создаётся только явным `init --demo`; её
геометрические фигуры и reference sheet — технические fixtures, не результат
GPT Images и не образец художественного качества. Они проверяют проигрыватели
без оплаты генерации. Для браузерного smoke использовать доступный Playwright
или браузерный инструмент; не добавлять браузерные зависимости в готовую игру.

Для подготовленного `--demo` можно запустить `node /skill/scripts/browser_check.cjs
/project` (одной командой). Нужен установленный Playwright; если он находится
в другом каталоге, задать `PLAYWRIGHT_PATH` его абсолютным путём. Проверка сама
поднимает временный HTTP-сервер на loopback, проверяет file/HTTP/подкаталог
в Chrome, Firefox и WebKit, сохраняет `qa/browser` и закрывает свои процессы.
Для части браузеров задать `TEST_BROWSERS`, например `chromium,firefox`.

Поведенческие ситуации при ревизии инструкций:

| Запрос | Ожидаемое решение |
|---|---|
| «Сделай спектакль по этому тексту» | Сначала спросить pygame/web/both; сохранить источник |
| «Создай web-спектакль по главе» | Не переспрашивать движок; обеспечить file:// |
| Новая wiki без sheet | Предложить общее/локальное хранение; листы раньше поз |
| Wiki с подходящими sheet | Переиспользовать ID и листы, не генерировать заново |
| Тот же герой в другой одежде | Вариант прежней личности с явным профилем |
| Пользователь отказался писать в wiki | Все материалы внутри постановки |
| Десять сцен или другой автор | Динамическое меню, никаких имён из прежних книг |

Не считать таблицу доказательством поведения агента: отдельно фиксировать
реально проведённые прогоны. Проверка шаблонов не проверяет работу генератора.
