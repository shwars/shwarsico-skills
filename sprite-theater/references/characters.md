# Character sheet и согласованность

## Найти и сохранить

1. Собрать весь изображаемый состав. Для wiki искать существующие sheet и их
   метаданные по `entity_id`, aliases и принятой структуре. Не предполагать, что
   карточки обязательно находятся в `wiki/characters`: возможен `protagonists`.
2. Сопоставить профиль: стиль, эпоха/возраст, лицо, костюм, версия. Подходящий
   лист переиспользовать. При нескольких равноправных профилях спросить выбор.
3. Если общий путь уже согласован, использовать его. Иначе предложить хранение
   в wiki один раз для следующих спектаклей либо внутри текущего проекта.
   Существующее разрешение не переспрашивать. Не создавать общую директорию
   до выбора пользователя. Локальный вариант — `assets/characters/sheets/`.
4. Новые профили и версии создавать отдельно, не заменять прежний лист.
   Смена костюма опирается на лист прежней личности; значимые изменения возраста
   тоже имеют явный профиль. После добавления в wiki не менять канонические
   карточки, индексы и сборщики без отдельной необходимости.

Рекомендуемая единица хранения — `<entity-slug>/<profile>/v1/`: `sheet.png`,
`sheet.json`, `prompt.txt`. Это рекомендация, а не миграция существующей wiki.
Существующий лист без метаданных сначала осмотреть; метаданные добавить рядом
или локально, не регенерировать годный образ только ради нового формата.

Минимальные метаданные:

```json
{
  "entity_id": "устойчивый ID из wiki или проекта",
  "profile": "paper-watercolor-adult-travel",
  "version": 1,
  "image": "sheet.png",
  "sources": ["source/book/ch01.md#^b0008"],
  "artistic_choices": ["Цвет глаз в тексте не указан; выбран серый."],
  "generator": "Codex built-in GPT Images",
  "prompt_file": "prompt.txt",
  "reference_files": []
}
```

## Сначала листы всего состава

Собрать общий художественный замысел: техника, палитра, степень условности,
свет, толщина светлой каймы. Для каждого героя описать отличия из источника
и отдельно авторские дополнения. Не переносить внешность героя другой книги.

Промпт листа: «Character reference sheet одного и того же персонажа [описание].
Полный рост: спереди, сбоку, сзади; крупный план лица и несколько выражений.
Одинаковые пропорции, черты лица, причёска, одежда и палитра во всех видах.
Нейтральные позы, полностью видимые конечности и головной убор. [Общий стиль].
Без посторонних героев и реквизита, закрывающего лицо». Фон листа может быть
нейтральным непрозрачным: лист — референс, не игровой спрайт.

Использовать встроенный GPT Images напрямую. Если лист или референс доступен
локально, сначала осмотреть изображение и передать путь как reference согласно
интерфейсу инструмента. Если опора только в переписке, включить именно нужные
изображения; не подменять отсутствующий референс текстовым обещанием.

Проверить, что разные виды показывают одного героя. Исправить ошибки до поз.
Для уже созданных удачных спрайтов без листа сначала вывести sheet на их основе,
сохранив лицо и костюм, затем использовать его для новых вариантов.

## Игровые изображения

Для каждой позы передавать sheet как reference; при необходимости также
удачную игровую позу. Промпт: «Тот же персонаж с character sheet: [поза/ракурс].
Сохранить лицо, пропорции, костюм, палитру и фактуру. Одна цельная полнофигурная
кукла, тонкая светлая кайма, настоящий прозрачный фон, без падающей на фон тени.
Головной убор, руки, обувь и весь нужный реквизит целиком; свободные поля».
Для спрайтов и отдельного реквизита включать прозрачный фон в параметрах генератора.
Шахматная заливка не считается прозрачностью. Подходящую позу использовать
повторно; не генерировать новый рисунок ради каждого покачивания.

Отдельно генерировать необходимые фоны без персонажей, в общем стиле и с
согласованной линией пола. Оставлять место для фигур и реплик. Реквизит должен
работать с руками и масштабом кукол; при поднятии сочетать позу, наклон и
ключевые кадры предмета. Скрытие/смена позы не должно оставлять предмет висящим.

В манифесте каждой фигурки указать локальный `sheet` и `sheet_origin`
(`entity_id`, `profile`, `version`, исходный путь при общем хранении).
Рядом сохранить промпт, список референсов и происхождение генерации.
Скопировать sheet и метаданные в проект: проигрывание не зависит от wiki.
Проверить лица и костюмы рядом на контактном листе; alpha-валидатор сходство
не устанавливает. Не исправлять художественные дефекты программным рисованием.
