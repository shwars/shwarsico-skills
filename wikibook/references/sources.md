# Подготовка источника и чтение большой книги

## Регистрация

Выбрать короткий читаемый `book_id` из строчных латинских букв, цифр, `_`, `-`.
`hist` зарезервирован. Название и `--series-order` задать по книге и циклу;
код не выводится из случайного имени временного файла. Уточнить преемственность:
одинаковое имя в независимых вселенных не создаёт общую личность.

Оригиналы сохранить неизменными. Не склеивать файлы физически и не перезаписывать
издание при исправлении OCR. Сохранять переводчика, структуру и происхождение.
Другой перевод/редакция — отдельная версия с явным сопоставлением адресов.

```text
python /skill/scripts/wiki.py --root /vault prepare --book-id book1 --input /vault/source/part1.fb2 --input /vault/source/part2.fb2 --title "Общее название" --series-order 1
```

Порядок `--input` существенен. Манифест хранит файлы и их SHA-256, отпечаток
упорядоченного набора (`ordered-source-set`), текстовые атомы, структуру,
единицы, блоки и примечания. Однофайловый отпечаток — хеш самого файла.
Не заявлять побайтовое равенство подготовленного текста: нормализуются пробелы
и разметка; проверяется сохранность и порядок атомарного текста.

## Что делает FB2-парсер

Учитывает XML namespace, вложенные sections, русские/английские обозначения
томов и частей с арабскими/римскими числами. Сохраняет абзацы, стихи, письма,
цитаты, подписи, заголовки и текст между дочерними sections. Заголовки контейнеров
также сохраняются в манифесте. Титульные единицы не считать событиями сюжета.

Адреса вроде `p01-ch01`, `v01-p01-ch01`, `epilogue`, `section-01` зависят от
реальной структуры. Для необычной системы заголовков проверить результат
и при необходимости расширить распознавание до первого содержательного прохода.
Не переименовывать уже цитируемые главы ради красивого оглавления.

У составной книги примечания разделены по физическому источнику, даже когда
номера начинаются заново. Поддерживаются ссылки `#n_1`, `#note1` и другие
существующие ID. Если структурные адреса файлов совпадают, добавляется
пространство `s01-`, `s02-`; повторная подготовка сохраняет этот выбор.

Проверить число частей, глав, дополнительных единиц и примечаний по оригиналу.
Не зашивать числа другой книги. Повторная подготовка сохраняет прогресс,
название и порядок, если они не переопределены; смена оригинала или адресов
прерывает операцию до изменения подготовленных файлов.

## Чтение и возобновление

`read <unit> --first N --last M` выдаёт включительный диапазон блоков, начиная
с 1. Заголовок показывает общее число блоков. Большие главы читать несколькими
диапазонами; при обрезанном выводе заново получить недостающий диапазон.
Проверить объединение диапазонов на отсутствие пропусков. Наличие манифеста
или краткого обзора не означает чтение.

`search` ищет по основному тексту и ограничивает число результатов. Использовать
для сверки имён и гипотез; поиск не заменяет последовательное чтение.
Примечания читать отдельно по `notes.md`, определяя их авторство и статус:
редакторские пояснения не равны художественным авторским сноскам. Если сноски
составляют само повествование, перед извлечением адаптировать подготовку так,
чтобы они были самостоятельными единицами основного текста с картой происхождения;
не исключать их из канона автоматически. Для длинных примечаний контролировать
полноту вывода. Обычный FB2-импорт сам такого литературного решения не принимает.

Перед продолжением: `status`, журнал вопросов, последняя завершённая единица,
реестр карточек/алиасов и соседний текст. Частично прочитанную главу не отмечать
полностью извлечённой. При раннем чтении будущего фрагмента не перескакивать
через неготовые единицы и не приписывать персонажам будущие знания.

Краткие обзоры глав, подборки упоминаний, карты сцен и тематические выборки
помогают навигации и памяти LLM. Они ссылаются на первичные блоки, не становятся
новым доказательством. Векторная база и отдельный API не нужны для первого прохода.

## Другие форматы

Встроенный `prepare` поддерживает FB2. Для EPUB, TXT/Markdown, DOCX и PDF
использовать доступный подходящий конвертер и проверить результат, не писать
новый движок wiki. Для сканов отдельно проверить OCR, порядок колонок и страниц.

Предпочтительный мост — проверенный производный FB2 с сохранённой иерархией
и примечаниями, затем обычный `prepare`. Исходный файл сохранить; рядом записать
его хеш, инструмент/версию, параметры и дату конвертации, карту страниц/разделов,
потери и выборочные сверки, достаточные для уверенности в полном тексте.
Производный файл не называть оригиналом издания. Разделить редакционный текст
и основной текст до извлечения.

Если доступен уже подготовленный адресуемый источник, его адаптер должен
выдавать контракт манифеста: `book_id`, `title`, `source_files` с хешами,
`source_sha256`, `fingerprint_kind`, `series_order`, `units` с порядком, путями
и блоками (`id`, `text`, `markdown`, `containers`), `notes`, контрольные числа
и хеши текста. Существующие инструменты чтения и графа используют этот контракт;
готового универсального импортера для произвольного Markdown в пакете нет.
Не менять контракт или адреса существующей wiki без явной миграции.
