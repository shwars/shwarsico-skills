# Карточки и факты

## Структура vault

`source/<book_id>/` содержит `manifest.json`, `progress.json`, `notes.md`
и `bychapter/<unit_id>.md`. Неизменные оригиналы обычно лежат в `source/`.

В `wiki/`: `protagonists/`, `events/`, `places/`, `objects/`, `organizations/`,
`context/` для концептов; `books/` для обзоров; `index.md`, `cal-timeline.md`,
`book-timeline.<book_id>.md`, `coverage.<book_id>.md`, `audit.<book_id>.md`,
`predicates.md`, `views/concepts.base`, `graph.json` для навигации и экспорта.
Не все служебные файлы требуют суффикса концепта.

Ссылки Obsidian — от корня vault, с прямыми слешами. Суффикс `.md` можно
опускать; суффикс книги сохраняется. В YAML ссылки заключать в кавычки.
Файлы должны быть безопасны для Windows: исключить `# ^ | : / \` и другие
запрещённые символы. `entity_id` остаётся читаемым независимо от имени файла.

## Данные

Плоский frontmatter: `entity_id`, `title`, `type`, `first_source`, `book_ids`,
`aliases`, `source_kinds`, `tags`. Типы: `character`, `event`, `place`, `object`,
`organization`, `context`. `related_events` и `participants` — проекции сборки.

Для события: `event_status` (`occurred`, `reported`, `disputed`, `refuted`,
`planned`, `hypothetical`), `date_text`, `date_precision`, `date_min`, `date_max`,
`sort_key`. У полностью неизвестной даты границы пустые; отрицательные годы,
вымышленные календари и неподдерживаемые даты описывать в `date_text`, не
выдумывать ISO-эквивалент. Встроенный валидатор границ ожидает ISO Gregorian.

В теле — один раздел `## Структурированные факты`, YAML fence `~~~yaml`
с корневым списком `facts` и, у события, `occurrences`.

Факт содержит:

| Поле | Значение |
|---|---|
| `fact_id` | Стабильный уникальный ID, например `Софья/факт-001`; не перенумеровывать |
| `subject` | ID карточки, в которой хранится факт |
| `predicate` | Единый словарь `wiki.PREDICATES`; расширять осмысленно, без синонимов |
| `object` или `value` | ID сущности/факта либо буквальное значение; ровно одно |
| `scope` | `canon`, `history`, `editorial`, `analysis` |
| `evidence_type` | `narrator`, `action`, `testimony`, `editorial`, `web`, `inference` |
| `truth_status` | `confirmed`, `claimed`, `disputed`, `refuted`, `unknown` |
| `sources` | Непустой список адресов блоков или внешних источников |

Дополнительно: `asserted_by`, `at_event`, `valid_from`, `valid_until`, `basis`
(ID фактов), `explanation`; у участия — `role`; у изменения — `property`,
`before_value`, `after_value`. Для `causes`, `requires`, `prevents` объяснение
обязательно. Причинный факт А → Б хранится у А; причины у Б — обратная проекция.
`valid_from`/`valid_until` в текущем инструменте ссылаются на сущности/факты,
а не содержат произвольные строки дат. Время пояснять также в тексте.

Пример появления: `{book_id: book1, unit_id: p01-ch01, block_id: b0002,
kind: воспоминание}`. Появление — место рассказа, а не дата самого события.
Ключи полей сохранять; пояснения и `kind` писать на языке wiki.

## Текст карточки

Персонаж: роль и имена; внешность (или явно отсутствие описания); черты и
характерные поступки; цели; отношения; знания и убеждения; изменения состояния;
связанные события. У краткого упоминания не выдумывать полноценную биографию.

Событие: что и в каком статусе произошло; участники и роли; место; датировка
и её основания; исход; причины, препятствия и последствия; изменения состояний.
Разделять сообщение о событии и само событие, когда раскрытие меняет сюжет.

Места: вложенность, перемещения и ограничения действий. Предметы: различимые
экземпляры, содержание/информация, переходы владения. Организации: роли,
членство и цели. Одинаковое описание двух предметов не доказывает тождество.

Отмеченную область `<!-- wiki:generated:start -->` … `<!-- wiki:generated:end -->`
не заполнять вручную. Новая книга дополняет ручной текст и факты, а сборка также
выводит профильные факты по разделам «Далее из другой книги: …».

## Python API

Добавить абсолютный каталог `scripts/` этого скилла в `sys.path` временного
авторского скрипта. Не полагаться на текущий каталог и не копировать движок.

```python
import sys
sys.path.insert(0, "/absolute/skill/scripts")
import wiki
import authoring as a

wiki.configure("/absolute/vault")
a.set_book("book1")
with wiki.authoring_batch():
    a.concept("Софья", "character", "p01-ch01", [1],
              "Посланница. В этом фрагменте внешность не описана.")
    a.event("Софья получает письмо", "p01-ch01", [2],
            "Софья получает запечатанное письмо.", participants=[("Софья", "получатель")],
            dates=dict(prefix="undated", date_min=None, date_max=None,
                       date_precision="unknown", date_text="Год не установлен"))
wiki.set_progress("book1", "p01-ch01", read=True, extracted=True,
                  summary="Письмо передано; содержание пока неизвестно.", questions=[])
```

Это пример вызовов, не утверждение о содержимом реальной книги. Перед созданием
проверить реестр и прочитать всю единицу. Примеры: [персонаж](../assets/character.example.md)
и [событие](../assets/event.example.md).

Основные помощники: `a.add_facts(id, records, sections=None)` автоматически
назначает следующие номера и пропускает точные повторения; `a.appearance(id,
unit, block, kind)` добавляет появление; `a.revise` изменяет выбранные поля
и сохраняет остальной текст. `wiki.ref(book, unit, block)` создаёт адрес.
Семантически одинаковые утверждения с разными источниками сопоставляет агент:
автоматическая дедупликация не доказывает их тождество. При дополнении
существующего факта сохранять ID и добавлять доказательства.

`a.event(causes=[(target, explanation)])` создаёт исходящую причинную связь
от создаваемого события к `target`. Не перепутать направление с причинами
создаваемого события. `changes` — кортежи `(id, property, before, after)`.
Для свидетельств задавать `asserted_by` и статус на уровне соответствующих фактов.

`wiki.authoring_batch()` — кэш одного писателя, не транзакция. Предварительно
проверять новые ID, ссылки и источники; при сбое проверить реально записанные
карточки перед повторным запуском. Не запускать миграцию внутри пакета.
