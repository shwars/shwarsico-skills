# Wikibook

Строить проверяемую wiki, пригодную для чтения, анализа, адаптаций и будущих
what-if сценариев. Основное содержание извлекает агент, а встроенные скрипты
подготавливают адресуемый текст, сохраняют карточки, проверяют и собирают граф.
Скрипты не вызывают LLM. Не писать эти инструменты заново для каждой книги.

## Начало или продолжение

1. Прочитать применимые инструкции проекта и проверить исходники, издание,
   текущие карточки и журнал. Корень vault содержит `source/` и `wiki/`,
   а не только каталог карточек. Выбрать устойчивый `book_id` и порядок цикла.
2. Для новой wiki адаптировать [шаблон AGENTS.md](assets/AGENTS.md.template),
   записав выбранные пути, книги, язык и договорённости; существующие правила
   дополнить, не заменять. Язык — указанный пользователем или язык его запроса.
   Технические названия полей и раздел «Структурированные факты» сохранять.
3. Для подготовки прочитать [sources.md](references/sources.md), для авторства —
   [schema.md](references/schema.md). Для каждой книги сначала подготовить
   источник и проверить полноту, затем последовательно читать и извлекать.
4. При продолжении запустить `status`; прочитать актуальные вопросы и реестр
   сущностей. Следующая книга расширяет общие карточки. Правила поиска,
   переименований и объединений — [identity.md](references/identity.md).
5. Работать небольшими законченными единицами по [extraction.md](references/extraction.md).
   Сохранять результат в Markdown и прогресс после каждой полностью выполненной
   единицы. По умолчанию закончить чтение, извлечение и отдельный аудит книги
   перед содержательной обработкой следующей; уважать иной заданный порядок.
6. Выполнить `validate`, `build`, повторную проверку и сверку навигации.
   Сообщить отдельно стадии покрытия, структурную проверку, метод смыслового
   аудита и оставшиеся вопросы. Подготовка файла или успех сборки не означают
   завершения чтения и проверки.

## Обязательные принципы

- Один персонаж — одна каноническая карточка в цикле. Идентификаторы читаемые
  и устойчивые. Проверять имена, псевдонимы, титулы, поколения и контекст.
- `.<book_id>.md` показывает первую книгу; позже дописывать в ту же карточку
  раздел «Далее из другой книги: …». `.hist.md` у человека означает отсутствие
  упоминаний в обработанном основном тексте; такое упоминание требует миграции.
- Извлекать всех различимых лиц, включая кратко упомянутых и безымянных,
  а события — при значимом изменении состояния, знаний, отношений или условий.
  Не превращать толпу в вымышленных отдельных людей.
- Существенные описания, изменения и связи подтверждать адресами блоков.
  Сохранять предысторию, неудавшиеся действия и повторные изложения событий.
- Различать канон, историю, редакционные примечания и анализ; внутри них —
  действие, свидетельство, убеждение, обвинение, план, опровержение и неопределённость.
  Не сглаживать противоречия и не переносить поздние знания персонажей назад.
- Причинность требует механизма и основания. Порядок изложения или соседство
  событий не доказывают причинности. План и видение не доказывают исполнение.
- Календарь сохраняет доступную точность; неизвестные даты не заполнять
  вымышленными днями. Книжный таймлайн хранит все появления события по тексту.
- Markdown — источник данных. Один факт хранить один раз у субъекта; обратные
  связи, JSON, индексы и Bases получать сборкой. Ручной текст и старые ID сохранять.
- Исторические справки проверять по внешним источникам и явно отделять от книги.
  Не исправлять литературный канон историей. Внешний контекст добавлять в
  согласованном объёме; не расширять его бесконечно за счёт чтения самой книги.
- Альтернативные ветки создавать по отдельному запросу. Рекомендации по
  состояниям, расхождению и адаптациям — [scenarios.md](references/scenarios.md).

## Встроенные инструменты

Требуются Python 3.10+ и PyYAML; зависимости — [requirements.txt](scripts/requirements.txt).
В командах заменить `/skill` абсолютным путём этого скилла, `/vault` — корнем
проекта. Запуск возможен из любого рабочего каталога. `--root` ставить перед
командой. Без него используется текущий каталог, а не каталог скилла.

```text
python -m pip install -r /skill/scripts/requirements.txt
python /skill/scripts/wiki.py --root /vault prepare --book-id book1 --input /vault/source/book1.fb2 --title "Название" --series-order 1
python /skill/scripts/wiki.py --root /vault read p01-ch01 --book-id book1 --first 1 --last 60
python /skill/scripts/wiki.py --root /vault search "Имя|Псевдоним" --book-id book1 --limit 30
python /skill/scripts/wiki.py --root /vault status --book-id book1
python /skill/scripts/wiki.py --root /vault validate
python /skill/scripts/wiki.py --root /vault build
```

`--input` повторяется для физических частей одной книги. Автоматический импорт
поддерживает FB2; другим форматам требуется проверенная нормализация, описанная
в sources.md. Не обещать наличие EPUB/PDF/DOCX конвертера.

Использовать [authoring.py](scripts/authoring.py) для создания и дополнения карточек,
фактов и появлений; перед работой вызвать `wiki.configure(root)` и
`authoring.set_book(book_id)`. Интерфейс и пример — schema.md. Авторство выполнять
одним писателем; `wiki.authoring_batch()` ускоряет пакет, но не является транзакцией.
Миграции выполнять вне пакета, с предварительным просмотром.

Не переносить в новый проект одноразовые скрипты с фактами другой книги.
Не считать `graph.json` актуальным до успешной сборки. Не использовать кэш
или пересказ вместо первичного текста, не отмечать непрочитанные диапазоны.

Проверка переносимых инструментов:

```text
python -m unittest discover -s /skill/scripts -p "test_*.py"
```
